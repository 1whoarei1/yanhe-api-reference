## 证据等级

| 等级 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 源码对照 | 某个固定修订确实构造了该路径、参数、签名或解析器 | 当前服务器一定还接受，或字段是完整官方规范 |
| 合成接口测试 | 客户端能处理指定的响应、异常和格式 | 线上接口及所有账号、课程一定可用 |
| 真实场景记录 | 某个授权会话、某个时间、某类资源发生过该行为 | 其它课程、权限、存储分支及未来版本都等价 |

接口索引每项的 `sourceProject/source/anchor` 是可定位证据。OpenAPI 中的例子全部是合成结构，不应被引用为实时抓包。源码锚点验证只读源文件，不执行参考代码。

## 后续核对建议

1. 先定位所属系统、接口编号和固定源码修订，避免将网页路由当 JSON API。
2. 读取请求只用本人有权访问的对象；日志保留方法、路径和状态，正文先脱敏。
3. 检查 HTTP、业务码、响应类型和必要字段，再做归一化；新增字段应保留原始响应。
4. 写入测试使用明确授权的目标、文件和环境；提交前后分别读取记录，结果不明时不要重复 POST。
5. 更新参数、字段、兼容分支和证据等级；未确认的行为写成待确认，不能用合成例子填补成真实结论。
6. 更新 `catalog/endpoints.json`、相关正文及合成示例，重新生成 OpenAPI 和索引，再执行离线检查。
